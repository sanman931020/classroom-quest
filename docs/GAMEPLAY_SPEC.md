# 核心玩法（第二階段起：班會大挑戰）

遊戲只有一個活動「班會大挑戰」，流程：**提出問題 → 主持討論 → 聆聽不同意見 → 做出決定 → 觀察決策影響 → 修正與反思**。所有結果由 `src/data/*Story.ts` 的資料與 `src/simulation/meetingImpact.ts` 的確定性規則產生，不使用 AI。

## 入口

學生輸入「我的班級」（≤12 字）與「我的名字」（≤8 字），存在本機 `classroom-quest-meeting-v1`，全程顯示於 HUD、黑板、布告欄、對話框與紀錄。可在主選單修改。

## 選擇主題與角色

- 主題一：**選舉班級幹部**（課本 p.5–6）
- 主題二：**班會提案：閱讀角怎麼用？**（課本 p.7–12）
- 角色：**主席**（主持）、**司儀**（宣布程序）、**記錄**（記錄內容）、**學生**（參與討論）。玩家不擔任的角色由 NPC 擔任（主題一：主席小宇、司儀浩浩、記錄小米；主題二：主席安安或玩家、司儀安安／小宇、記錄阿哲）。

## 主題一：選舉班級幹部

| 步驟（課本） | 玩家操作 | 情境分支（依角色） |
|---|---|---|
| 一、提名人選 | 幹部工作配對（可選）；選擇提名人選；確認提名 | 主席：「他很好笑」不是理由→請說理由；司儀：宣布時提醒說理由；記錄：好朋友要求寫大一點；學生：認真提名／提名好朋友／開玩笑提名 |
| 二、徵求附議，進行討論 | 徵求附議（同學舉手）；完成討論 | 主席：有沒有附議、起鬨；司儀：請候選人說服務計畫；記錄：記下附議與計畫；學生：起鬨、候選人比一比（課本甲乙） |
| 三、舉手表決 | 選擇支持對象→第一次表決 **14:14 平票**→處理平票→再表決 **16:12** | 平票處理（四角色各有選項）；主席：重複舉手；司儀：一位一位唸；記錄：畫正字、不可改票；學生：依自己判斷 |
| 四、宣布結果 | 宣布結果 | 謝謝候選人、尊重沒當選的同學、任期、接受結果 |

票數為遊戲模擬並標示。完成後進入「觀察影響」：選舉後一週（reason／cooperate／kind 標記與儀表決定）。

## 主題二：班會提案

1. **提出問題**：提案單（問題／提案／理由）＋引導句。若尚未選出班長，可先玩主題一或使用預設（班長安安）。
2. **召開班會**：正式六程序 班會開始→主席報告→班長及各股股長報告→提案討論→臨時動議→散會（會後請導師指導），不可跳步（`nextMeeting`）。
   - 每個程序有該角色的情境決策，未處理前不能完成程序。
   - 提案討論：徵求附議→邀請舉手（佇列 FIFO）→主席同意→發言（取得論點卡：主張／理由／可能影響）→聽完再下一位；插話、離題、偏心、還有人沒發言等事件在對應時機觸發。
   - 影響預測：每個方案最可能感到不方便的人（沒有唯一正確方案）。
   - 表決：教材固定示範 6／18／4（標示「不是實際學生投票」）。
   - 服從多數、尊重少數：選擇配套措施（遠一點、小小聲、書櫃隔開、試行一週；「不用再管」為反例），自動寫入少數意見。
3. **觀察影響**：一週模擬（方案＋配套＋會議中是否提出書本問題＋秩序儀表）。
4. **修正反思**：「如果重來一次」建議、模擬實驗室（換方案 A/B/C 與配套比較笑臉天數，可採用新配套修正決議）、反思（引導句）、會議紀錄。

## 影響規則摘要

- 儀表起始 60，依選項 effect 加減，夾在 0–100。
- 角色表情：選項 `feel` 依序覆蓋。
- 結局：該角色在該主題做出的「好做法」比例（主題二另含是否照顧少數）≥80% 高、≥50% 中、其餘低；四角色×兩主題各有三段文字。
- 所有結果確定、可重現（見 `tests/meeting.test.ts`）。

## 保留的第一階段核心

`engine.place / simulate / serviceComplete` 與閱讀角、服務站資料仍在程式中並有單元測試，但目前沒有介面入口。
